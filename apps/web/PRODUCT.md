# Grill Me

Grill Me is a personal, local-first practice companion for developers. It supports coding challenges, implementation reviews, standalone and challenge quizzes, and revisiting prior practice. These workflows deserve equal care.

A fresh installation asks where app data and challenge workspaces live before the backend starts, with defaults that preserve existing installations and named child folders for custom parents. Users describe what they want to learn, choose scope and difficulty, build in their own editor, and submit code or connect a local project. Each challenge keeps a local workspace folder for code, notes, and artifacts, with starter material seeded once and detected editors one action away. Reviews provide evidence and actionable feedback. Users decide when to mark a challenge completed; acceptance, difficulty, and quiz scores remain separate concepts. Quiz answers save automatically and attempts can be resumed or retaken. Quiz detail uses All quizzes for navigation, a full readable title, and older/newer controls for saved attempts; it does not duplicate the library with a quiz dropdown. Start controls sit below the title rather than in a vertically centered empty screen. Standalone and challenge quizzes share the same layout: the original prompt opens through a secondary View prompt action, only question content scrolls, and progress plus previous/next/submit controls stay available. A compact combined title/action header and bottom question navigation leave the question pane at full reading width. Question typography uses a moderate weight and relaxed line spacing.

Home centers the challenge and quiz composer above a chronological list of recent practice grouped by relative day. The composer scrolls away with the page. The list shows 15 items initially, supports up to two more batches, then links to the full Challenges table.

The interface should be comfortable for sustained practice: readable task text, compact navigation, clear controls, and accessible keyboard operation. Keep page insets and gaps between related controls compact so more content is visible. Preserve readable prose and usable control sizes. The app supports light and dark themes and narrow touch screens. This is a personal workspace, without a team or project-management layer. Local profile selection is not authentication.

The interface uses shadcn/Radix, with T3Code as a reference for spacing, surface hierarchy, compact navigation, and settings organization. Preserve Grill Me's original neutral charcoal/white palette, inverted monochrome actions, full-color logo, and orange Grill difficulty identity. The user explicitly rejected both the gray-blue replacement and the saturated navy/cobalt replacement. Refinement means improving tonal separation, contrast, borders, and interaction states within the original palette; it does not authorize changing the hue family. Practice, collections, settings, and preferences share compact top navigation instead of the former application sidebar. The challenges collection uses a table with status tabs, search, filter, and sort controls. Collections emphasize search, filters, and sorting. Settings and Preferences keep their section navigation visible while content scrolls beneath the page header. Challenge detail uses a single title row with the Files button, a text-only section list on wide windows, and a responsive facts rail in Overview. Files opens the read-only panel on the right. The Overview rail shows lifecycle actions below the split editor button: the label opens the selected editor and the separate arrow opens workspace actions, review and submission in Review, the full agent transcripts in Activity, and quizzes in their own tab. New challenges keep brief generation and project setup in one progress screen, including any clarification or setup decisions. Activity aligns the trajectory and transcript with the challenge content and groups transcripts by Preparation, Reviews, and other active operations; retired discussion and hint records remain stored but have no controls or tabs in the app. Codebase preparation, resume, retry, and fresh setup read as one continuous chat without numbered attempts, turn headers, or session dividers. Older split preparation histories appear in the same conversation. Reviews retain their numbered, independently saved scorecards, selected through compact history dropdowns in Review and Activity. Before the first review, show the completion criteria. A saved scorecard leads with the verdict and next step, then shows criterion evidence and links to its run in Activity. The challenge Overview keeps the original prompt in a collapsed disclosure above the brief. Copy prompt appears inside it, while Copy challenge lives with the Overview actions and copies the generated brief. Challenge quiz lists show search, filters, and sort on demand. The trajectory provides a searchable run list with run statistics and display options on demand. Selected records open in a resizable full-height right inspector over the workspace; it can expand for reading, and closing it returns focus to the selected row without resetting the run list. Captured context is readable by section and remains available in its original form under Stored. Activity shows compact elapsed work summaries with live timing during a run and saved timing afterward. Activity follows new messages smoothly only while the reader stays at the end; reading history pauses following, and reduced motion is respected. The optional read-only Files panel can expand to fill the challenge workspace and restores without losing the selected file or tree state.

Loading placeholders follow the destination layout and appear only for perceptible waits. Keep the existing controls and shell visible when the route and profile are known.

Preserve existing data, API contracts, frozen challenge requirements, scoring rules, explicit completion, code attachment behavior, and quiz save/recovery behavior when extending the UI. Source product details live in the repository README.

This is a personal developer tool. Keep screens focused on controls, data, and results. Omit taglines, promotional empty states, routine instructions, and duplicate descriptions. Preserve field names, accessible semantics, technical limits, keyboard shortcuts, errors, and meaningful state.

Typography uses locally served Inter Variable for interface/prose and IBM Plex
Mono for code and paths. This follows the user's explicit typography refinement
request; the original palette and softened border system remain authoritative.
